Le point de départ

01Le constat

On accumule des vêtements sans jamais avoir de vue d'ensemble de sa garde-robe, et on achète en ligne sans savoir ce qu'un vêtement donnera sur soi.

  • Une garde-robe désorganisée, difficile à exploiter au quotidien.
  • L'essayage impossible avant l'achat en ligne.
  • Aucun outil personnel pour visualiser et tester ses tenues.
La réponse

02Juju, une garde-robe virtuelle

Une application web personnelle qui numérise la garde-robe et permet d'essayer virtuellement chaque pièce sur son propre mannequin, grâce à l'IA.

Numériser

Chaque pièce est photographiée, détourée et classée (catégorie, marque, couleurs, matières).

Se modéliser

L'utilisateur capture son mannequin sous quatre angles.

Essayer

L'IA génère un rendu de la pièce portée sur le mannequin.

Positionnement « wardrobe-first » : la garde-robe est la porte d'entrée ; l'essayage et les statistiques gravitent autour. Cible : tout particulier soucieux de mieux gérer et valoriser ses vêtements.

Conception de la base · 4/5

14Les relations

One-to-Many

Un utilisateur possède plusieurs articles, photos et essayages — chacun n'appartient qu'à lui.

Many-to-Many

Couleurs et matières via tables d'association ; la matière porte un pourcentage de composition.

Suppression

CASCADE pour les données propres, RESTRICT pour les référentiels partagés.

Le pattern « snapshot » des essayages

La table essayages_log conserve une copie des informations au moment de l'essayage, plutôt qu'une simple référence. L'historique reste cohérent même si l'article est ensuite modifié ou supprimé.

Composant métier sécurisé

16Authentification

  • Mots de passe hachés avec bcrypt — jamais stockés en clair.
  • Sessions par JWT signé, vérifié à chaque requête.
  • Middleware authRequired en garde de toutes les routes privées.
  • Pages légales RGPD (mentions, données personnelles).
// middleware — garde des routes privées
function authRequired(req, res, next) {
  const token = req.headers.authorization?.split(" ")[1];
  if (!token) return res.status(401).json({ erreur: "Non authentifié" });
  try {
    const payload = jwt.verify(token, process.env.JWT_SECRET);
    req.user = { id_utilisateur: payload.sub };
    next();
  } catch {
    res.status(401).json({ erreur: "Jeton invalide" });
  }
}

Démarche de résolution de problème

23Deux failles trouvées, corrigées

Marques partagées entre comptesOWASP A01

Problème : les marques créées par un compte apparaissaient chez les autres — table globale partagée, sans rattachement à l'utilisateur. Contrôle d'accès rompu.

Correctif : marques rendues propres à chaque utilisateur (clé étrangère + unicité par utilisateur) et contrôle de propriété à la création comme à la modification.

Connexion sans limite de tentativesOWASP A07

Problème : la route de connexion ne limitait pas le nombre d'essais — une attaque par force brute sur les mots de passe était possible.

Correctif : limitation du nombre de tentatives (rate limiting) par IP et par compte, en complément du hachage bcrypt volontairement lent.

Leçon retenue : la sécurité se vérifie cas par cas — un référentiel n'est pas toujours partagé, et toute porte d'entrée publique doit être protégée contre les abus.
